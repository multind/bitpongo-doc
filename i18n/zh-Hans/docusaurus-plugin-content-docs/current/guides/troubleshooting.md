## 显示运行中，却没有交易

![评估、真实成交、记录和通知的区别示意](/img/guides/controls-zh.svg)

1. 核对账户、策略 ID、启用状态和**执行时区**。
2. 定投检查下次时间、执行记录、价格区间和买入条件。触发次数不等于成交次数。
3. F&G 检查启用后是否有**新的**指数数据进入对应区间，以及方向、剩余轮数和并发限制。
4. 核对 API 权限和后端当前出口 IP 白名单。现货查询成功不代表合约权限正常。
5. 检查正确钱包中的**可用余额**，以及分配到每个币种后的最小订单和精度。
6. 结果不明确时先查交易所订单，不要盲目重复下单。

## 看到什么，接着查什么

| 现象 | 下一步 |
| --- | --- |
| 密钥/IP/权限错误 | 逐项检查密钥有效性、具体产品权限和服务器白名单 |
| 余额不足 | 钱包类型、可用/冻结余额和整轮分配金额 |
| 触发了却没有订单 | 执行记录、条件门槛、新信号规则和工作进程 |
| 已受理但没有成交记录 | 交易所订单状态和服务端成交核对，不要直接重发 |
| 剩余少量仓位 | 实际部分成交、最小交易限制和复核状态 |
| 没收益曲线 | 成交/快照是否存在、筛选范围和加载错误 |
| 时间相差几个小时 | 用明确时区把同一时刻转换后再对比 |

## 没收到通知

分清四步：**生成事件 → 消息入队 → 平台接受 → 接收端收到**。前一步成功不能单独证明最后一步成功。

- App：系统权限、本机注册、账户/事件开关、网络和系统展示设置。
- 邮件：验证后的接收地址、垃圾邮件和运营方邮件服务。
- Telegram：绑定账户正确、已点 Start、没有屏蔽机器人。
- Webhook：平台、URL、签名匹配，单个接收端和总开关都开启，平台响应正常。
- 逐级感知：是否仍在五分钟确认窗口中，下一组尚未到发送时间。

## 有用的反馈应包含什么

提供 App 版本/构建号、安全的策略或事件 ID、**带时区**的时间、原始错误文案和脱敏截图，说明预期与实际情况。不要发送密码、验证码、API 密钥、服务账号文件或完整 Webhook URL。收集证据前不要通过删记录来「重置」问题。
